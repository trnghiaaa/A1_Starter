What is Steering?
8
Steering behavior is a rule that tells a game character how to move in a way that 
looks natural and intelligent, based on what it sees or wants to do.  
Why We Use Steering in Games
Steering is used whenever we want believable motion

How Movement Happens?
Imagine driving a car:
▪
Position: where your car is right now on the road.
▪
Velocity: how fast and in what direction we’re driving/the speed of something given a direction!
▪
Acceleration: how your speed changes: pressing gas, braking, or turning the wheel. 
Now in games, we update these things many times every second => frames per second or FPS.
➢Acceleration changes velocity.
➢Velocity changes position.
▪
FPS: how often the game updates each second. 
▪
Δ time (delta time): the amount of time that passes between two frames(two updates). 
▪
Δt  is the inverse of FPS => Δt= 1/ FPS
The Tiny Physics Behind Steering
The Formulas:
For each frame, we do:
new_velocity = old_velocity + acceleration * dt
new_position = old_position + velocity * dt
Remember: dt means “delta time”, how many seconds have passed since the last frame (usually around 
1/60 of a second).
The Tiny Physics Behind Steering
Now we ask: what makes acceleration happen?
In real life, forces change our velocity:
▪
Gas pedal pushes the car forward.
▪
Brakes apply force backward.
▪
Turning the wheel changes the direction of the force.
In our game, steering behaviors are those forces!
▪
Each steering behavior computes a steering force: a small vector that says “turn this way”
or “slow down a bit”.
▪
Then we convert that force into acceleration: 
acceleration = steering_force / mass, if we treat mass = 1 (to keep things simple), then:
acceleration = steering_force

Week3 – Finite State Machine in Games
▪A finite State Machine (FSM) is a simple computation model that moves 
among a limited set of states in response to inputs.
Finite State Machine
Simply:
▪A simple computational model that has a fixed, known set of states, lives 
in exactly one state at a time, reads input symbols one by one, and moves 
between states by following rules.
▪It starts in a designated start state. Some states are marked accepting. 
When the input ends, the machine says yes if it sits in an accepting state, 
otherwise no.
Why do we need something like FSM?
▪Game characters must decide what to do based on the world around them. 
We want behavior that is fast, believable, and easy to debug. 
▪Different AI tools exist, and FSM is a simple, reliable one for many cases.
Finite State Machine in Games
An FSM for a videogame character consists of:
▪States, which define the character’s various behaviours. A character is 
always in one state (never zero, never more than one).
▪An initial state.
▪Events, which cause transitions between states.
▪A transition function that says where to go next when an event happens
▪A character is always in exactly one state at a time
Finite State Machine in Games
A Finite State Machine is a small set of named states plus rules that tell you when to 
switch from one state to another.
Example:
An  enemy with 2 states:
PATROL - wander around randomly.
CHASE - move toward the player if they are close enough.
The rules are:
▪
If the enemy is in PATROL and the player comes close, switch to CHASE.
▪
If the enemy is in CHASE and the player gets far away, switch back to PATROL.
Finite State Machine in Games
A Finite State Machine has:
▪
A set of states, like Wander, Chase(seek), Flee
▪
One initial state
▪
Inputs or events that can occur
▪
A transition function that says where to go next when an event happens
▪
A character is always in exactly one state at a time

Finite State Machine in Games
From Steering Behavior to States
Each state plugs into one steering behavior:
▪
Wander state calls wander steering
▪
Chase state calls seek or pursue
▪
Flee state calls flee
▪
This is simple behavior switching rather than blending. You can still blend if you want 
inside a state.
Two common FSM Styles:
▪
Moore style: actions live in states, so you run code each update while you are in that state
▪
Mealy style: actions occur on transitions
Game devs usually find Moore more intuitive.

Finite State Machine in Games
Problem Scenario
You are controlling a simple snake AI with a tiny FSM. The FSM has three states: Patrol, Aggro, and Harmless. The
machine starts in Patrol. From Patrol, if the frog enters the detection radius, the event FrogInRange occurs, and the
snake switches to Aggro. From Aggro, if the frog moves outside the de-aggro radius, the event FrogOutOfRange
occurs, and the snake returns to Patrol. From Aggro, if a bubble hits the snake, the event HitByBubble occurs, and the
snake becomes Harmless. From Harmless, when the snake reaches its Home position, the event ReachedHome
occurs, and it goes back to Patrol. If no event that matches an outgoing arrow is true on a given frame, the FSM stays
in the current state.
States: Patrol, Aggro, HarmlessStart: Patrol
Transitions:
Patrol → Aggro on FrogInRange
Aggro → Patrol on FrogOutOfRange
Aggro → Harmless on HitByBubble
Harmless → Patrol on ReachedHome
If nothing matches, stay in the same state.
